# Executable governance case studies

Start with a human need, follow the transaction and identify the decisions that can create consequences. These fictional cases model real transaction patterns, not observed incidents or production integrations.

| Case | Central policy question |
|---|---|
| [Travel and hospitality](travel-hospitality.md) | May an agent commit to changing hotel terms? |
| [Personal shopping](personal-shopping.md) | May an agent create an economic commitment? |
| [Healthcare](healthcare-agent.md) | Does scheduling authority extend to sensitive disclosure? |
| [Insurance](insurance-claim-agent.md) | Does claim submission authority extend to final settlement? |

Use the [case-study method](governance-case-study-method.md) to formulate policies and the [cross-domain failure analysis](cross-domain-failure-analysis.md) to identify common failure mechanisms. Run the [action-governance walkthrough](action-governance.md) for the minimal execution boundary.

All cases run offline. A local permit is not an executed transaction, verified external authority or independent assurance. Proposed controls are not implemented merely because they appear in a diagram.
