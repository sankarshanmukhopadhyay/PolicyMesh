# PolicyMesh v0.20.0 — Fail-closed action governance and verifiable decision evidence

## Changes
- Missing, null and incompatible operands cannot establish successful rule evaluation.
- The evaluator rejects empty policies and invalid request envelopes; denial retains precedence over deferral.
- New receipts identify evaluation semantics and rule failure categories.
- SDK and CLI verification bind a receipt to retained inputs and reproduce the decision.
- Executable conformance vectors and CI evidence cover rule behavior, receipt verification and consumer interfaces.

- Version-pinned DTG/VTI alignment and a synthetic supplementary local policy gate with negative regression cases. No live VTI interoperability or conformance is claimed.

## Compatibility and migration
This release intentionally changes authorization outcomes for incomplete inputs, string membership, implicit boolean/numeric comparisons and empty policies. Review policies using the [action semantics guide](../concepts/action-evaluation.md). Existing unmarked receipts remain digest-checkable but are not reproduced under the corrected semantics. New receipt fields require consumers using strict older schemas to update them.

## Validation
Run `pytest`, `python scripts/validate_repository.py` and `python scripts/action_conformance.py`. The latter writes source-linked execution evidence. Consult the release commit's CI for actual results.

## Limits
Local reproduction does not authenticate issuers, prove external mandate legitimacy, establish current permission or enforce business-side effects. Independent interoperability and production certification are not asserted. Protect retained evidence and receipts from unnecessary disclosure.
