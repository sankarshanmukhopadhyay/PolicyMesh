# PolicyMesh v0.21.0: Executable Governance Case Studies and Failure Analysis

## What's new

- Four reader-facing case studies cover travel, shopping, healthcare and insurance with fictional transaction narratives, authority boundaries, state diagrams, textual alternatives, policy matrices and failure hypotheses.
- 31 executable scenarios, indexed against request and expected-outcome fixtures. Four new cases cover missing refundability, missing commitment type, missing disclosure purpose and payment-evidence resolution.
- Each runner checks retained-input decision reproduction and writes a verification report alongside the receipt.
- Pinned DTFC correlations illustrate selected local mechanisms without asserting canonical failure-case satisfaction.

Start with the [case-study portfolio](../examples/index.md) and [cross-domain failure analysis](../examples/cross-domain-failure-analysis.md).

## Compatibility

The v0.20.0 evaluation semantics and receipt contracts are unchanged. Runners add verification reports and enforce expected local outcomes. Package, SDK and service version metadata are aligned.

## Validation

Run `pytest`, `python scripts/validate_repository.py` and `python scripts/action_conformance.py`. The release attaches source-linked results, including actual scenario runner tests.

## Limits

All domain inputs are fictional. Business lifecycle diagrams are illustrative, not implemented state machines. No real payment, booking, health disclosure or claim is executed. No external authority, consent validity, observed harm, independent assurance or DTFC conformance is established. Maturity remains implementation-draft under active validation.
