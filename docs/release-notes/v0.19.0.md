# PolicyMesh v0.19.0

v0.19.0 expands PolicyMesh from a single business-facing Travel reference case into a deliberately varied **personal-agent governance portfolio**.

## Added

- Personal Shopping Agent: bounded purchase authority, category/merchant policy, recurring-commitment denial and approval escalation.
- Healthcare Appointment & Consent Agent: separate scheduling and purpose-limited disclosure policies, provider verification, explicit consent and revocation.
- Insurance Claim Agent: evidence-gated claim submission and separately bounded settlement authority.
- Personal Agent Governance concept model covering observe/recommend/prepare/commit, `DEFER`-driven approval/evidence loops, revocable mandates and negotiation.
- Reusable pattern notes for bounded delegation, human approval, purpose-limited disclosure and consequence-sensitive authority.

All examples use the same generic `ActionPolicy`, `evaluate_action` and `ActionDecisionReceipt` implementation. They do not make PolicyMesh authoritative for identity, mandates, healthcare consent law, insurance coverage, merchant trust or domain execution.

## Why this release matters

A new reader can now compare multiple verticals and see which part is PolicyMesh and which parts remain external. The examples also provide a concrete personal-agent enforcement pattern: place PolicyMesh between a proposed consequential action and the MCP/API/tool call that would execute it.
